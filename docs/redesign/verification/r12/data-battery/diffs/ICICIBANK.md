**Counts: 18 ok · 7 watch · 1 mismatch · 0 fabrications.**

- **Identity: clean.** Symbol resolution, exchange, and name all agree with the reference (and the app correctly disambiguated ICICIBANK.NS from the US ADR IBN and from lookalike tickers).
- **Core valuation and quality metrics are accurate and internally coherent**: price, market cap, 52-week high/low, drawdown, dividend (declared amount and yield on a consistently-disclosed forward basis), ROE, and earnings growth (MRQ YoY) all land within tolerance of the reference's primary or cross-checked figures. P/E, EPS, and book value all show the *same* small, expected skew toward ICICI Bank's **consolidated** financials rather than standalone — a real but well-understood and consistently-applied basis choice, not a bug.
- **One real bug candidate: `revenue_growth` (MRQ YoY) = +66.9%,** against a reference-computed +1.99% (standalone) / +2.49% (consolidated) — off by roughly 27–34x on both bases. This can't be explained by the standalone/consolidated split (neither basis is anywhere close), and the sibling `earnings_growth` field from the identical provider call and identical `growth_basis` label matches the reference closely, so the growth block isn't uniformly mis-based. The inflated TTM revenue figure (row 17, +11–28% over the reference-implied TTM) is consistent with the same upstream revenue-definition/period issue. **Recommend the team spot-check `revenue_growth`/`revenue_ttm` sourcing for Indian bank tickers before trusting it in a published brief** — this is exactly the kind of number that would mislead a user reading the "Latest Quarter" section (which the app's own narration already hedges: *"this figure likely reflects treasury/other income volatility"* — a reasonable but insufficient explanation for a 27x gap).
- **One latent internal inconsistency (non-fabrication):** the top-level `/fundamentals` snapshot returns `dividend_per_share_ttm: null` while the research-tool's fundamentals call in the same session, ~60–90s later, returns `11.0` for the identical field. The rendered brief shows the correct value, so no user-facing harm this run, but the null path is a real gap worth tracking down.
- **Two "watch" items are pure basis-definition mismatches, not errors**: institutional/insider holding percentages (Yahoo's global 13F-style categories vs India's FII/DII/Promoter regulatory shareholding-pattern buckets) and the 52-week price-change % (acutely anchor-date-sensitive; the reference pack disagrees with itself here by ~0.6pp, and the app's reading is a third plausible value in the same range).
- **No fabrications found.** Every app-asserted value traces to a real provider call (`yfinance` or `nse_direct`); the one clear numeric problem (revenue growth) is a **wrong/mis-defined value from a real source**, not an invented one.

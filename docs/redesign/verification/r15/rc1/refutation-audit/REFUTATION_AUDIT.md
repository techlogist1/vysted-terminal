## Adjacent findings

- **R15-AGENT-003** — candidate new register entry
  - **Title**: A Delegate run halted by a budget ceiling still proposes the halted round's undispatched host actions (host_actions not retracted on HALT_NOTICE_TOOL)
  - **Proposed severity**: high (a proposed-changes gate entry the user can approve for an action the agent runtime never actually dispatched — a gate-integrity bug, not cosmetic)
  - **Repro**: Scripted provider emits a valid `write_note` tool_use followed by `done(...)` reporting ~100k tokens; `RunBudget(max_tokens=1000)` trips mid-round so the run status ends `error` (budget halt) with `dispatched == []`. Despite that, `row.host_actions == [write_note]` survives, and `src/lib/delegate-runs.ts:279` enqueues those undispatched `host_actions` into the proposed-changes gate regardless of run status.
  - **Root cause**: `agent_runtime.py:2016` yields each `tool_use` to the caller before the `:2036` halt check runs; `run_manager.py:294-301` appends every yielded host action unconditionally, and the `HALT_NOTICE_TOOL` branch (`:302`) only flips `halted` — it never retracts the host actions already appended for that round.
  - **Suggested test**: `test_run_manager.py::test_a_halted_rounds_host_actions_are_not_proposed` asserting `row.host_actions == []` and `dispatched == []` when a round halts on a budget ceiling.
  - Note: the entry's own (R15-AGENT-003) repro — a scripted provider capped at 6 tool rounds — still holds fixed at HEAD (7 provider rounds, 6 yielded == 6 dispatched, clean stop message; `test_b3_runtime_capped_round` + halt tests pass). This is a distinct trigger (Delegate BUDGET HALT, the path added by R15-AGENT-037's batch-7 fix), so it is registered as a new, adjacent defect rather than a reopen of R15-AGENT-003.

# Fresh install and first launch of the 0.9.0 release bundle (operator-attended)

**Verdict: PASS, with one deviation and one test-method note.** The release bundle built at r15-launch `1fddb2b1` installed from its dmg, launched, raised the expected LEAD-143 login-keychain prompt (answered by the operator), and reached a healthy, populated cockpit.

- **Source (deviation).** The brief asked for the dmg from the draft GitHub release. `gh release download v0.9.0 --pattern '*.dmg'` failed twice at 01:46 IST with `net/http: TLS handshake timeout` on `release-assets.githubusercontent.com`, so the lead installed from the local dmg that is the draft's asset: `<scratchpad>/bundle-rc2b/src-tauri/target/release/bundle/dmg/Vysted Terminal_0.9.0_aarch64.dmg`, sha256 `9940d41b7ed6725aaabb6bb1709dc48b4f8ec51facd0696e376c68401139bc53`, 228,480,607 bytes (the draft asset reports the same size; it was re-uploaded from this same file at 01:36 IST).
- **Install.** `hdiutil attach -nobrowse -readonly`, `ditto` of `Vysted Terminal.app` into `<scratchpad>/gui-close/Applications/` (never `/Applications`, which holds the operator's 0.8.0 copy), detach. Bundle: version 0.9.0, id `com.vysted.terminal`.
- **Launch.** `open -n --env VYSTED_DATA_DIR=<scratchpad>/gui-close/data` at 01:47:23 IST (empty data dir).
- **Keychain prompt (R15-LEAD-143).** SecurityAgent pid 60957 appeared at 01:47:28, 5 s after launch. The operator, at the Mac, clicked **Always Allow**; the reply reached the lead at 01:55 IST.
- **Health.** The app's own sidecar on 127.0.0.1:50891 answered `/health` with `version 0.9.0`; openbb-mcp bound on 50892; logs showed live provider traffic by 01:56.
- **Capture.** `01-first-run.png` (window-only, `screencapture -l`, registered in `r15/CAPTURES.jsonl`): status CONNECTED, default model Ollama (local) qwen2.5 7B, Watchlist with live ^NSEI 22,421.95 and RELIANCE.NS 1,167.70 quotes (EOD 2026-10-01, weekend), News with a sentiment-tagged RELIANCE.NS item, empty Portfolio and Equity Overview placeholders, chat empty-state with four suggestions. A full-screen capture taken at the same time showed the operator's editor instead of the app and was deleted unregistered.
- **Quit.** By pid at 01:58:26 (app 60924 and its children); nothing left running.

**Test-method note (not a defect).** No terms dialog and no onboarding appeared. `VYSTED_DATA_DIR` moves only the data dir; the release build keeps the first-launch terms acknowledgement in the login keychain (`app-meta:first-launch-terms`, `src/lib/keychain.ts:129`) with a legacy `app-meta:onboarding-complete` beside it (current onboarding flags live in the data dir's app-meta). Earlier builds on this Mac had stored those items, and the operator's Always Allow let this build read them, so the launch was a fresh *install* but not a fresh *profile*. The true first-run walk (terms, onboarding, keyless lane) is scenario UI-7, driven on an isolated `HOME` (debug build, dev keystore) in this same round.

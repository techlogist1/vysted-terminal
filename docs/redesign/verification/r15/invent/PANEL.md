# R15 Stage E: judge panel verdict

Read-only ideation over the ranked backlog (`BACKLOG.md`: 58 ranked rows plus one unranked candidate, 59 judged). No building, no code edits, no app runs. Backlog rows are referred to by BL id and title only.

## 1. Method

**Who judged.** Judge A: the sceptical power user, strongest tier, adversarial. Judge B: **not returned** (the harness delivered `null`, no case cards). The panel therefore has one independent judge and this synthesis, which re-read every killed row, every small-build candidate and the top three against HEAD (`ac227f43`, branch `004-r4-experience-rebuild`) before ranking. Where the synthesis diverges from Judge A it is named in section 3; there are no judge-vs-judge disagreements to resolve because there is no second score set.

**Angles.** Adversarial on value to the real user (the serious individual investor, small-cap and India-aware), fit with the moat (agent-first, local-first, BYOK, witnessed answers), feasibility inside the existing architecture and boundaries, demo quality (populated screenshot or chat transcript), lifecycle cost.

**Criteria.** Five 1-5 scores per row. With one judge the averaged score equals Judge A's score. Kill: a row killed by both judges is dead; a row killed by one (all eleven, since Judge B is absent) was re-read against the backlog row and the objection and decided with a written rationale (section 7).

**Ranking rule.** Survivors are ordered by the value the real user gets per build-day: `user_value x (feasibility / 5) / days`, where `days` is the backlog estimate except where Judge A's objection states a smaller residual it verified at HEAD (BL-03: 3 days, BL-15: 4 days as the exchange_financials reframe). Rows within 0.1 of each other are a tie and are broken by lifecycle, then moat fit. The feasibility factor discounts value the row promises but cannot deliver inside its own estimate.

**Boundaries applied.** Trading is out permanently (no broker connectivity, order placement/proposal/review, paper brokerage, live/paper switch); the user's own tracked portfolio with manual holdings, cost bases, P&L on real prices, notes and watchlists stays and the agent may reason over it. Locked: two-tier research, the R9 design system ('on' or 'on, extends it' with one primitive), the dev keystore, the plugin system, no return of the retired broker plugin. Tier-4 files out of reach for the one small build: `types/plugin.ts`, `.github/`, `src-tauri/tauri.conf.json`, `LICENSE*`, the section 6.5 safety files, `CLAUDE.md`. Local-first, BYOK and the keyless default (llama3.1:8b via local ollama, keyless data sources) keep working; no new heavy dependency; nothing that needs a funded model lane, a paid data source or a GUI-only proof. The one small build is S band (2-4 days), one workflow on a 16 GB M1 Mac between two release candidates, demoable, release line stays green.

**HEAD facts the verdicts lean on** (verified this pass, not taken from the judge): `routers/fundamentals.py:137` runs `correctness_gate.apply_witnesses` on GET (BL-01 landed); `services/exchange_financials.py` serves five filed periods per NSE/BSE listing with `filed` date and `url`, `FiledPeriods.year_ago()` and `cadence()` exist, `_PERIODS_WANTED = 5` already covers the newest period's QoQ and YoY; the terminal snapshot already carries `holdings[]` with `quantity`, `costBasis`, `marketValue`, `pnl` (`src/modules/chat/context-provider.ts:38-70`); `agent_runtime._render_terminal_preamble` (line 404) renders only `Portfolio: N positions, total value` (line 460) and `_render_notes_line` (line 507) already reads the focused symbol's note; `read_notes` is in the catalog (`catalog.py:1181`); `deriveMetrics` (`brief-blocks.tsx:412`) is called from `BriefPanel.tsx:641` and `BriefBody` (`brief-blocks.tsx:1061`).

## 3. Defects in the spec

**D1. AC-11 can never pass with the spec's own fixture (blocking).**
- The Portfolio panel's `Wt` column is per row (`PortfolioPanel.tsx:650`), and rows are per position, not per symbol (`metrics.ts:102-111` maps `positions`; per-row weight at `:156-160`).
- The fixture enters TANLA as two lots (`TANLA` and `TANLA.NS`), so the panel shows two TANLA rows. At the fixture prices those rows would read about 29.2% and 19.5%, and no cell reads `48.6%`.
- Fix: AC-11 checks that the brief's weight equals the sum of the TANLA rows' weights, to one decimal. Alternatively, the verifier reads the published `portfolio` bus event with `evaluate_script` and recomputes the weight from it.

**D2. AC-8's literal `48.6%`, and the figures in section 1, depend on live prices (blocking).**
- The panel marks holdings with live quotes (`fetchPositionQuotes`, `PortfolioPanel.tsx:232`). The fixture's 48.6% and -20,750 assume TANLA at 770.50 and KAYNES at 4,070.
- A verifier on the rc3 build will see different numbers, so AC-8 as written fails on a correct build.
- Fix: AC-8 asserts that the three cells are present and first, and that the weight equals the value recomputed from the bus event at capture time (the same check as the D1 fix). The fixed vector stays in the unit tests only.

**D3. The demo fixture's bare `TANLA` lot may never be marked (blocking for the owner drive).**
- Quotes are looked up by `position.symbol.toUpperCase()` (`metrics.ts:103`).
- unverified: whether `fetchPositionQuotes` resolves an unsuffixed `TANLA` to the NSE listing. Opening `fetchPositionQuotes` and the sidecar quote route's resolver would verify it.
- If the bare symbol does not resolve, that lot's `marketValue` is null. The aggregate then goes unmarked, the card shows `YOUR POSITION` alone, and AC-8 fails for a reason unrelated to the build.
- Fix: enter the lots as `TANLA.NS` and `TANLA.BO`. This still exercises the suffix rule (unverified: that both suffixed listings quote; the same check as above verifies it). Alternatively, the verifier confirms both rows are priced before the brief runs.

**D4. `test_no_portfolio_or_empty_holdings_renders_nothing_new` has an ambiguous baseline.**
- With `portfolio: {"holdings": []}`, `if pf:` is truthy, so the `Portfolio:` line still renders (`agent_runtime.py:450-460`).
- Compared with the same state without the `portfolio` key, the output differs, and the test fails on a correct build.
- The intended baseline is the same state without the `holdings` key. Better still, the test pins the full expected preamble as a literal string. A post-change renderer cannot be compared against the pre-change one, so the phrase "byte-identical baseline" promises something the test cannot deliver.

**D5. The sidecar binary rebuild for the running-app ACs is missing.**
- AC-8 to AC-12 run "on the rc3 candidate build". The preamble lives in the PyInstaller main sidecar (`externalBin`, per the repo's sidecar rules).
- The integrator section does not say the main sidecar is rebuilt (`pnpm sidecars:build`, or the staleness-aware ensure script) before the verifier's drive.
- Without the rebuild, AC-12 tests the old preamble.
- Fix: add one integrator step, and have AC-12 record the sidecar binary's mtime against the merge commit.

**D6. The Python and TS rules stay in agreement only by hand-copying.**
- "The card and the preamble agree by construction" is not true. They are two implementations (`_holding_key` and `holdingKey`, plus the two aggregation functions) pinned by vectors copied into two test files.
- A later change to the regex or the suffix set on one side passes both suites.
- Acceptable for S. The spec should name this as a risk rather than claim construction.

**D7. The token and privacy delta is not stated.**
- Today the preamble carries only the position count and the total (`:460`).
- The held line sends up to 12 held symbols to the model on every turn, including cloud BYOK providers, whether or not the user asked about the portfolio.
- This does not cross a boundary. The user's tracked portfolio is explicitly allowed (`PANEL.md` Boundaries), and the same data is already one `get_portfolio` call away. Section 8 should still list it next to the token cost.

**D8. AC-9's "hovering shows the title" is weak evidence.**
- A native `title` tooltip is not reliably captured by the Quartz screenshot path.
- The verifier should read the cell's `title` attribute with `evaluate_script`, which works on an occluded webview according to the repo's visual-verification notes.

**D9. Unit-test gap: the regression that matters most is not pinned on the renderer.**
- `brief-position.test.ts` checks labels and values. No test asserts that the three position cards precede the semantic items when a `derived` leg is present.
- The equity fixture in `brief-blocks.test.ts:223` has a derived leg, but the spec's lead-order test does not say which fixture it uses.
- Fix: run the lead-order assertion on a structured bundle with a `derived` leg, so a later reorder (`[...semantic, ...positionItems]`) fails.

**D10. The card may label the average cost with the wrong currency (low).**
- Section 2.3 item 3 formats `avgCost` in the brief's instrument currency, but holdings carry no currency (`TerminalHolding`, `context-provider.ts:38-51`).
- The key match (a bare symbol, or `.NS`/`.BO`) makes a cross-currency match unlikely, but not impossible: a bare `BRK.B` holding and a US-quoted brief is a correct match, and an INR-denominated cost typed on a US listing would be mislabelled. Worth one line in the risks.

Not defects:
- The spec drops the panel's `holdingFor` selector. That is correct: the store has no marks (`portfolioFromStore` sets `marketValue: null`, `context-provider.ts:205`).
- Rejecting the wire variant is also correct.

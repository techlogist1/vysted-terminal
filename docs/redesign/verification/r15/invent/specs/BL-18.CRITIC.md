## 3. Defects

**D1 (blocking for AC-6). Fundamentals facts will not format "exactly as the metric card formats
it."** The spec routes `fundamentals.*` facts through `formatDerived`, which calls
`formatInstrumentMoney(value, cur, false)` (non-compact, `brief-blocks.tsx:161-162`). The card
formats `revenue_ttm` with `formatInstrumentMoney(num, cur)` (compact default, `:334-337`,
`format.ts:139-150`) and `eps` with `formatPrice` (`:325`), not as currency. A correct build per
section 2.3 renders "Revenue 14,402,000,000.00" beside a card that reads compact, and EPS with a
currency the card does not show. Fix: give fundamentals facts the card's own formatter per field
(compact money for `revenue_ttm`/`net_income_ttm`, `formatPrice` for `eps`, `formatFractionPercent`
for `roe`/`profit_margin`), or weaken AC-6 to derived keys only.

**D2 (blocking for AC-11). The byte-identical test cannot see a regression.** The listed test
compares `BriefBody` with and without `diff: undefined` in the same build, so both sides run the
new code. AC-11 asks for identity with head `6bc6d378`. Fix: writer C captures
`renderToStaticMarkup(BriefBody)` for two existing fixtures at the base before editing and commits
it as a literal expected string, then asserts against it.

**D3 (blocking for C1 as written). The brief store is not on the dev bridge.**
`dev-mcp-bridge.ts:33-58` does not expose `useBriefStore`, and the file is in no writer set.
Fix: C1 and C2 read `briefHistory` from `GET /workspace/__autosave__`, stated as the only route;
or add `brief: useBriefStore` to the bridge in set C (dev-only, stripped from production at `:27`).

**D4 (blocking for C4 as written). The seeding sequence has no sidecar to talk to.** C4 says to
quit the app, then GET and POST `/workspace/__autosave__`. The sidecar port is assigned by the
Tauri core at launch (project CLAUDE.md, Stack), so with the app quit there is no endpoint.
unverified: whether the sidecar outlives the app, or where `services/workspace_store` writes the
file. With the app running, any history change autosaves over the edit. Fix: do the GET/POST with
the app running and no brief activity after the POST, then relaunch; or edit the store file on
disk after naming its path.

**D5. The "first publish defines the fingerprint" answer to Judge B holds only in AUTO.** Both
publishes ride the proposed-changes gate (`agent_runtime.py:1256-1257`). In review mode the user
can reject the auto-publish and approve the model's own publish, whose `structured` the model
wrote. The fingerprint is then the model's. The allow-lists and shape guards still bound it, but
section 2.7 point 4 overstates. Fix: state it, and add one vector where the model's `structured`
is the first publish.

**D6. The "same shadow rule as `deriveMetrics`" claim is wrong.** `deriveMetrics` drops a raw
card only when the derived value is non-null (`:447-453`), and never shadows raw `market_cap`. The
spec skips raw `market_cap`, `dividend_yield`, `revenue_growth` and `earnings_growth`
unconditionally, so when the derived leg is absent or null, a raw revenue-growth change is
invisible. Fix: make the skip conditional on the derived value being non-null, as the card does.

**D7. The strip's stagger step is under-specified.** `staggeredItemCount` gains 1 only if the
strip is its own `motion.div` with `childProps` inside the stagger parent (`brief-blocks.tsx:
1085-1092`). The spec says "wrapped in the same `dimMetrics` opacity class" but not that it is a
motion child. A plain `div` makes the +1 wrong and the AC-12 test still passes if it only asserts
"disabled longer". Fix: name it a `motion.div {...childProps}` and assert the exact settle
duration.

**D8. C6 has no mechanism.** "With the network lane down for filings" names no way to make the
leg fail on the rig. Fix: name one, for example a US symbol with the `sec-edgar-mcp` sidecar
stopped, which `fast.py:458-478` says reads as `provider_error`; otherwise C6 is the unit test
only, and the doc should say so.

**D9 (minor). Filing source precedence is unstated.** Section 2.3 lists three shapes "in this
order" without saying whether the first match wins or the lists union. A DEEP brief that carries
both `filings` and `disclosures` gives different "new" counts under the two readings. Fix: union,
deduped by key.

**D10 (minor). Blob growth is under-counted.** `buildWorkspacePayload` (`workspace.ts:610-635`)
writes every slice, global ones included, into every named save, so each named workspace file also
carries `briefHistory` (up to the spec's ~600 KB). The spec counts the autosave slot only. It does
not change the verdict.

**D11 (minor). Release docs unnamed.** Set D's files are "the lead names them". The verifier cannot
check the release-doc refresh until the lead lists them.

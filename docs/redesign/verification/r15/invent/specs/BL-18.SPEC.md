## 1. Goal and user-visible outcome

A user who researches a name they looked at before sees, at the top of the new brief, a
"Changed since <date>" strip that leads with what can only change when the company files: new
exchange announcements or SEC filings since the last brief, filing facts that moved (promoter
holding, reported growth, net income, dividend per share, EPS, ROE and the like), and
cross-source conflicts that appeared or were resolved. Values that move with the market (price,
market cap, P/E, drawdown, 52-week figures) sit in one collapsed "Market moved (N)" line.
Everything unchanged folds into "N figures unchanged". A leg that failed in either run reads
"Not compared" with the reason. It never reads as "nothing new". The strip costs zero tokens,
makes no network call and works keyless. It is computed on the renderer from the two briefs'
provenance-tagged `structured` bundles, never from prose.

**Owner-drive demonstration.** The owner opens the app with the keyless default model, asks
"research TANLA", and the brief lands with its metric cards and no strip, because this is the
first brief on the symbol. The owner quits and relaunches. The brief comes back archived, as
it does today (`src/store/brief.ts:224-240`), and the owner presses Refresh in the archived
banner (`src/modules/research/BriefPanel.tsx:495-525`). The new brief opens with the strip:
"Changed since 26 Sep, 10:14". The first line reads "No new filings or filing-fact changes" (or
lists them if the company filed in between). Under it sits a closed "Market moved (6)"
disclosure that opens to lines such as "Price 812.40 → 806.10", then "31 figures unchanged".
For the populated screenshot the verifier seeds an older baseline (section 5, certification
C4). The strip then leads with a new "Outcome of Board Meeting" announcement, promoter holding
52.10% → 49.80% and a new CONFLICT line, with the market values still folded away. This is the
journalist-4 moment ("anything new on Viyash?", `ideas/journalist.md:196-202`).

### 2.2 Where state lives

- **The fingerprint, not the brief.** The store keeps a compact `BriefFingerprint` per symbol
  instead of a second `ResearchBriefData`. The markdown and the news leg are never kept. The
  fingerprint holds only what the diff reads. `fingerprintBrief(brief)` returns `null` (nothing
  is recorded) unless all four of these hold: the brief has a `symbol`, has
  `execution.runId`, has a `structured` object, and carries no `disambiguation`. Shape
  (versioned):

  ```ts
  interface FactValue { value: number | null; label: string; basis?: string;
                        unit?: BriefDerivedValue["unit"]; reason?: string; group: "filing" | "market" }
  interface FilingItem { key: string; title: string; date: string | null; url?: string }
  interface BriefFingerprint {
    v: 1; symbol: string; createdAt: number; runId: string; currency?: string;
    legs: { derived: boolean | null; fundamentals: boolean | null; price: boolean | null; filings: boolean | null };
    facts: Record<string, FactValue>;          // "derived.<key>" | "fundamentals.<field>" | "price.price"
    conflicts: BriefMetricConflict[];          // raw, rendered through the existing conflictLines
    filings: FilingItem[];                     // cap 25, newest first as served
    sourceUrls: string[];                      // dedupeSources(brief.sources) urls, cap 40
  }
  ```

  `legs.x` is `true` when the leg is ok, `false` when it is present and not ok, and `null` when
  it is absent.
- **Per-symbol history in the brief store.** `src/store/brief.ts` gains
  `history: Record<string, { latest: BriefFingerprint; previous?: BriefFingerprint }>`, plus
  `historyBundle()` and `fromHistoryBundle(raw: unknown)`. `publish` (`:184-197`) records only
  on the `"published"` result, so a `stale_run` publish records nothing. `fromBundle`
  (`:224-240`), `clearBrief` (`:218-220`), `failRun` and `watchdogTick` never touch history.
  `resetBriefStoreForTests` (`:250-252`) also resets `history: {}`.
- **The record rule (pure, `recordFingerprint` in `brief-diff.ts`).** The key is
  `historyKey(symbol)`: uppercase, trimmed, with the same `.NS|.BO|.NSE|.BSE` strip as the
  private `baseSymbol` at `src/lib/host-actions.ts:180-185`. It is duplicated in 5 lines rather
  than importing `host-actions.ts` into a pure lib. There are two cases:
  - Same `runId` as `entry.latest`: the entry is left unchanged, because the first publish of
    a run defines its fingerprint. The runtime's auto-publish carries the research tool's own
    `brief` verbatim (`sidecar/services/agent_runtime.py:1251-1272`), and the tool passes the
    engine's `structured` through (`sidecar/services/agent_tools/research.py:198`, `:269`).
  - Different run: the entry becomes `{ latest: fp, previous: entry?.latest }`.

  The map is capped at 20 symbols, and the entry with the oldest `latest.createdAt` is evicted.
- **Persistence.** The brief slice's `read` writes a companion key. `PersistedSlice.key` allows
  this: "`read` may also write a companion key" (`src/lib/workspace.ts:231-232`). The new key
  is `SerializedWorkspace.briefHistory?: BriefHistoryBundle`, declared next to `brief`
  (`:147-151`). `restore` calls `fromHistoryBundle` only when `"briefHistory" in workspace`
  (older blobs keep `{}`). `fromHistoryBundle` drops every malformed entry and never throws.
  `subscribe` becomes `onChange(useBriefStore, (s) => s.brief, (s) => s.history)`. Scope stays
  `global`, like `brief`, so loading a named workspace does not restore it
  (`:234-240`). No `WORKSPACE_MIGRATIONS` step is needed, because version 0 is
  "today's shape with optional fields" (`:196-201`). `serializeWorkspace` (`:642`),
  `deserializeWorkspace` (`:656`) and `autosaveLayout` (`:1046`) are unchanged: they iterate
  `PERSISTED_SLICES` (`:300`), so the slice entry is the single edit.

### 2.3 The diff (pure, `diffBriefs(prior, next)` in `src/lib/brief-diff.ts`)

- **Fact keys and groups.** Only these keys are read. Everything else is ignored.
  - **Derived leg.** Every entry of `structured.derived.data` except `conflicts` that passes
    the same shape test as `isDerivedValueLike` (`brief-blocks.tsx:187-195`: object with
    `value` and a string `label`) is recorded as `derived.<key>`. The sidecar's full key list
    is `_PROMPT_KEYS` (`sidecar/services/research/semantics.py:1231-1249`).
  - **Filing group, derived keys** (an allow-list, which only moves on a filing):
    `dividend_per_share`, `dividend_per_share_ttm`, `dividend_declared`, `revenue_growth`,
    `earnings_growth`, `revenue_growth_computed`, `earnings_growth_computed`,
    `reported_net_income`, `normalized_net_income`, `promoter_percent_exchange`,
    `institutions_percent_exchange`.
  - **Market group, derived keys.** Every other derived key: `market_cap`,
    `drawdown_from_high`, `fifty_two_week_change`, `fifty_two_week_high_exchange`,
    `fifty_two_week_low_exchange`, `dividend_yield`, `market_cap_witness`, and any key the
    sidecar adds later. An unknown key defaults to the collapsed group, so noise can never lead.
  - **Filing group, fundamentals leg** (`types/data.ts:130-215`), recorded with a synthesized
    label and unit so the existing formatter renders them: `eps` (currency), `roe` (fraction),
    `profit_margin` (fraction), `debt_to_equity` (ratio), `revenue_ttm` (currency, basis =
    `financial_currency` when present), `net_income_ttm` (currency, same basis).
  - **Market group, fundamentals and price.** `pe_ratio`, `forward_pe`, `peg_ratio`,
    `price_to_book`, `beta` (all ratio), `fifty_two_week_high`, `fifty_two_week_low`
    (currency), and `price.price` (currency, from `Quote.price`).
  - **Keys deliberately not read.** Raw `market_cap`, `dividend_yield`, `revenue_growth` and
    `earnings_growth` are skipped because the derived leg owns them. This is the same shadow
    rule as `deriveMetrics` (`brief-blocks.tsx:445-455`).
- **Change rule.** A leg's keys are compared only when that leg is `true` in both fingerprints.
  Otherwise the leg goes to `notCompared`, with the reason "unavailable in the <date> run" or
  "not pulled by the <date> run". A key counts as changed in four cases:
  - it is present in only one of the two briefs (a conditional derived fact appeared or
    disappeared, such as `revenue_growth_computed`);
  - it is null on one side only;
  - both values are numbers and `|a-b| > 1e-6 * max(1, |a|)`;
  - both values are null and the `reason` strings differ.

  Anything else is unchanged and counts toward `unchanged`.
- **Filings.** `FilingItem`s are extracted in this order:
  1. `structured.filings` ok with `data.announcements[]` (the IN FAST leg). The shape is the
     `corporate_announcements` result (`sidecar/services/agent_tools/disclosure_tools.py:78-87`,
     wrapped by `_structured_value` at `sidecar/services/research/fast.py:242-265`, routed at
     `:451-481`). Each item maps to `key = attachment_url ?? exchange|ts|headline`,
     `title = headline`, `date = ts`.
  2. `structured.filings` ok with `data.filings[]` (the US leg,
     `sidecar/services/agent_tools/sec_tools.py:71-74`, `sidecar/models/sec.py:29-41`,
     `:148-155`). Each item maps to `key = accession`,
     `title = form_type + (period_of_report ? " for " + period_of_report : "")`,
     `date = filed_date`, `url = edgar_url`.
  3. `structured.disclosures` ok with `announcements[]` (the DEEP/iter IN floor,
     `sidecar/services/research/iter.py:377-385`, shape at
     `sidecar/services/research/disclosures.py:161-167`), read with the same rule as case 1.
     This key is not declared in `BriefStructured` (`types/brief.ts:47-64`). It is read as
     `(structured as Record<string, unknown>).disclosures`, and no type changes.
     `unverified: that a DEEP brief's published structured carries "disclosures" end to end`.
     To verify, run one deep brief and read `structured` on the rig. If it does not, the leg
     reads "not pulled", which is honest either way.

  A filing is **new** when three things hold: its key is not among the prior's keys, `date` is
  not null, and `Date.parse(date) >= prior.createdAt - 86_400_000`. The one-day grace covers
  SEC's date-only `filed_date`. Items that were unseen but are older are back-fill, not new.
  `newFilingsSaturated = next.filings.length > 0 && every next item is new`. The strip then says
  "at least N (feed cap)". The FAST leg asks for 20 (`fast.py:448`).
- **Conflicts.** Keyed by `(kind ?? "") + ":" + field` (`types/brief.ts:103-136`). The diff
  returns `added` and `resolved` raw conflicts. The strip renders them through the existing
  private `conflictLines` (`brief-blocks.tsx:264-304`), in the same file.
- **Sources.** `newSourceCount` counts the next brief's URLs that are not in the prior's. It is
  a count on the tail line only. The source rail is unchanged.

The output model is:

```ts
interface BriefDiff {
  since: number;                                   // prior.createdAt
  newFilings: FilingItem[]; newFilingsSaturated: boolean;
  facts: FactChange[];                             // group "filing" only; FactChange = { key; before: FactValue | null; after: FactValue | null }
  conflictsAdded: BriefMetricConflict[]; conflictsResolved: BriefMetricConflict[];
  market: FactChange[];
  unchanged: number; newSourceCount: number;
  notCompared: string[];                           // e.g. "Filings: unavailable in the 26 Sep run"
  currency?: string;                               // next.currency
}
```

### 2.4 The strip (UI)

`ChangedSinceStrip` is a new component in `src/modules/research/brief-blocks.tsx`. It is not
exported and renders only through `BriefBody`. `BriefBody` gains an optional prop
`diff?: BriefDiff | null`. When the prop is absent, the output is byte-identical to today. The
strip renders as the first child of the motion container (`:1085-1092`), before
`MetricsBlock`, wrapped in the same `dimMetrics` opacity class so an archived brief's strip
reads as archival.

The strip is built from primitives that already exist:

- the section container classes of `MetricsBlock` (`border-charcoal-700 bg-charcoal-925 border`, `:759`);
- a header row with `hud-label` "Changed since <d MMM, HH:mm>", using the `toLocaleString`
  options of `ArchivedBanner` (`BriefPanel.tsx:504-509`), and a right-aligned tertiary
  "N unchanged".

It holds these rows, in order:

1. New filings, at most 5, then "and N more". Each row has a `text-micro` uppercase chip "NEW
   FILING" in `text-charcoal-400`, the title, and the date in tertiary. The title links when
   `url` is present, as a plain anchor with the existing link classes of `SourceRow`.
   `unverified: SourceRow's exact anchor classes`; the writer reads `BriefPanel.tsx`
   `SourceRow` and copies them.
2. Filing-fact changes: "<label> <before> → <after>" in `font-mono tabular-nums`. Values are
   formatted by the existing private `formatDerived` + `withBasis` (`:155-184`), with
   `isSignedDerivedField` (`:202-204`) applied to the unprefixed key. A null side renders "—"
   plus its `reason` in tertiary.
3. Added conflicts, with the existing CONFLICT/DEFINITIONAL chips and tones (`:820-839`).
   Resolved conflicts get a "RESOLVED" chip in `text-charcoal-500`.
4. When rows 1-3 are all empty, a single secondary line: "No new filings or filing-fact
   changes."
5. `<details>` (closed) summary "Market moved (N)", listing the market changes in the format of
   row 2. There is native precedent in `src/components/SettingsPanel.tsx`.
6. A tail line in tertiary: "N new web sources", then each `notCompared` entry prefixed "Not
   compared:".

Colour rules: no amber and no green/red. The signal colours are reserved for data direction in
P&L columns (`docs/DESIGN_SYSTEM.md:114-132`), and hierarchy comes from the three tiers
(`:134-148`). Spacing uses allowed steps only (`scripts/audit-design-tokens.mjs:4-12`).

`BriefPanel.tsx` changes in three places:

- It reads `useBriefStore((s) => s.history)` next to `:603-604`.
- It computes `diff` with `useMemo` using the rule in 2.1.
- It passes `diff` to `BriefBody` (`:863`) and changes `staggeredItemCount` (`:647`) to
  `(diff ? 1 : 0) + (metrics ? 1 : 0) + blockCount`. Without that change the PDF/PNG export
  gate unlocks one stagger step early, which is the BRIEF-2 class `:620-624` warns about.

### 2.7 The panel's objections, answered one by one

1. **Judge A: "Price-derived metrics change daily so the strip is never empty."** Market values
   never lead. They are an explicit collapsed group, and unknown keys default into it. When
   only the market moved, the lead line is "No new filings or filing-fact changes", which is
   the answer the returning user wants.
2. **Judge A: "Re-research is rare enough that the prior is weeks stale and 'everything
   changed'."** Filing facts move only on filings, so a weeks-old prior still gives a short
   lead list. The header names the prior's date, new filings are capped at 5 shown with a
   total and a saturation marker, and the market group stays one closed line at any count.
3. **Judge B: "the strip always says something changed."** Same mechanism as 1. The counts sit
   in the header, and the first sentence is about filings.
4. **Judge B: "the diff is only as stable as the brief's structured keys, which vary by
   model."** The concern is real. `publish_brief` lets the model pass `structured` (catalog
   schema `sidecar/services/agent_tools/catalog.py:1500-1508`). It is answered on four
   fronts:
   - The fingerprint reads fixed sidecar key allow-lists only (2.3) and never display labels.
   - A value that fails the `isDerivedValueLike` shape is absent, and a failed leg is "Not
     compared".
   - A fingerprint is recorded only for briefs that carry an execution record.
   - The first publish of a run (the runtime auto-publish of the tool's own bundle) defines the
     fingerprint, so a model's later same-run re-publish with a paraphrased `structured`
     cannot replace it.
5. **Backlog lifecycle: "breaks only if it diffs display labels instead of stable keys."**
   Keys are `derived.<sidecar key>`, `fundamentals.<field>` and `price.price`. Labels are used
   for display only.
6. **Backlog risk: lead with filing facts.** This is 2.3's group rule. The journalist sheet's
   "separate filing facts from market-moved values" (`ideas/journalist.md:222-223`) is the
   allow-list.
7. **Implied by the honesty rule: a lane outage must not read as "nothing new".** A leg missing
   or failed in either run is stated in "Not compared" and is never folded into "unchanged".
8. **Dependency BL-02 ("announcements since the prior").** Its core has landed at this head.
   `_BSE_ANN_WINDOW_DAYS = 180` is at `sidecar/services/corporate_disclosures.py:120`, and the
   FAST leg requests 20 announcements (`fast.py:448`). No further dependency.

## 8. Risks and the rollback

- **Blob growth.** Worst case is about 20 symbols × 2 fingerprints. Each is capped at 25
  filings × 160-char titles, 40 URLs, and around 35 facts, so an estimated ≤ 15 KB each and
  ≤ 600 KB total. `unverified: the sidecar's workspace POST body limit`; the check is to read
  the `/workspace` router in `sidecar/routers/`. If a limit bites, halve `HISTORY_CAP`.
- **The DEEP `disclosures` passthrough may not reach the published brief** (2.3). The result is
  "Filings: not pulled", which is honest but less useful for DEEP briefs. FAST briefs carry
  `filings`.
- **Wrong group for a key.** A future sidecar key lands in the market group by default. The
  failure is too quiet (a fact hidden in the closed group), never too loud.
- **Mis-scaled provider values** (the rupee-scale class, BL-05) would show as a filing-fact
  change. The diff states what the tool said and does not re-witness it. The strip is only as
  right as the legs it compares. The correctness gate at `routers/fundamentals.py` serves the
  panel's GET, not the brief bundle. `unverified: whether apply_witnesses runs on the research
  snapshot path`.
- **Stagger or export regression.** Pinned by acceptance criterion 12.
- **Rollback.** One branch, merged as one merge commit. `git revert -m 1 <merge>` removes the
  strip, the store field and the slice companion key together. A blob written by the reverted
  build keeps a harmless `briefHistory` key, which the index signature
  (`workspace.ts:173`) accepts and nothing reads. No sidecar or data migration needs
  undoing.

## 9. Open questions the writer must NOT guess

Each question carries the default this spec chooses. The writer builds the default, and the
lead or operator overrides it.

1. **Should undated announcements count as new?** Default: no.
2. **What grace window applies before `prior.createdAt`?** Default: 24 h.
3. **Should the strip show on a restored archived brief?** Default: yes, dimmed with the
   metrics.
4. **What caps apply?** Default: 20 symbols, 25 filings, 40 source URLs, 160-char titles.
5. **Should `.NS`, `.BO` and bare listings share one history?** Default: yes, via `historyKey`.
6. **What numeric tolerance counts as a change?** Default: relative 1e-6, so any real change
   counts. Filing facts do not jitter, and market jitter is folded anyway.
7. **Is there a clear-history control?** Default: none in this build. History is replaced as
   the user re-researches and evicted at the cap.
8. **Should "Market moved" open by default?** Default: closed.
9. **Should named-workspace loads restore history?** Default: no (scope `global`, like `brief`).
10. **Should new web sources be listed by title?** Default: count only.
11. **Can two briefs of different depth (FAST and DEEP) be compared?** Default: yes. Keys are
    depth-independent, and a leg one side lacks is "Not compared".
12. **Should the diff show when the brief has no `symbol` but `structured.resolved` names one?**
    Default: no record, no strip.
13. **Which release docs does set D refresh, and does the lead cut `r15-rc3` per the tail
    rule?** Default: the lead decides. This spec touches neither the tag nor any operator-only
    action.

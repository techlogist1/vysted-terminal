## Tactical Tornado verdict

**Risk: medium-high.** The individual stores are small, well commented and mostly correct in isolation. The layer as a whole was built one teammate at a time, and the store boundary does not hide the decisions that matter:

- **Two stores own the same state.** `agent-spaces.ts` and `research-spaces.ts` both replace the live `chat-history` transcript, and neither knows the other exists or that a stream may be in flight.
- **One store owns nothing.** `workflow.ts` is a complete SSE consumer and notification queue with no production caller. The node editor re-implements the stream privately, so the one feature that depends on the store (desktop notifications) is dead.
- **One store advertises what it cannot do.** `keybindings.ts` persists and displays 11 remappable shortcuts but owns no dispatch. One binding honours a remap, six have no handler at all, and four are hard-coded elsewhere.
- **Async slices get no shared primitive.** Every fetch slice hand-rolls status, error and cache handling, and none carries a request generation, so a stale response overwrites a newer one (proven for SEC).

Flag count (pass B): 14 red flags across 12 files. The most damning pattern is the `workflow.ts` header comment (lines 17-23), which promises a dispatcher contract that no code path fulfils. The sidecar node then returns `notified: True` (`sidecar/services/workflow_nodes/builtin.py:337-344`) for a notification that never appears.

## Overall impression

The stores work well as dumb containers: small, typed, mostly synchronous, with thoughtful SSR-safety and render-loop hygiene. They fail as a state layer. They do not own the decisions that span them: which transcript is live, who dispatches a shortcut, whether a response is still current, and how a store talks to the sidecar. Each of those decisions is re-made (or not made) at the call site. The single biggest opportunity is one thread-owning conversation store: chat-history keyed by thread id, with streams writing to `(threadId, messageId)`. That removes finding 1 and the stale-brief-publish path it enables.

## What's working

- **`brief.ts`** is a real state machine (`BriefPanelState` union, `mirrorOf` as the single derivation, a `stale_run` guard, restore-always-archives). The mirror field keeps legacy readers working without leaking phases into them. It is the model the rest of the layer should copy.
- **`search-settings.ts` / `settings.ts` migration** (`migrateSearchSettings`, `parseDefaultAgentId` plus the sentinel) is pure and total: garbled or legacy blobs fold to safe defaults, and the async key confirmation is isolated in `reconcileMigratedTierB`.
- **Selector stability discipline** (frozen empties, `seq` counters, pre-computed `customSummaries`) is consistent across the layer and has structurally killed the `useSyncExternalStore` loop class.

## Priority issues (top 5)

- **[P1] Transcript ownership split across three stores.** Principle 3 / 7. Symptom: unknown unknowns. `agent-spaces.ts:43-64` and `research-spaces.ts:178-198` swap `chat-history` under a running stream. **Fix:** move threads into `chat-history` (`threads: Record<id, ChatMessage[]>`, `activeThreadId`) and keep streaming writes addressed by thread id. A research space becomes a thread keyed by space name, and a switch never discards a pending message. (COD-frontend-stores-1)
- **[P1] Dead workflow store vs private node-editor run loop.** Principle 1. Symptom: change amplification plus a dead feature. **Fix:** have `NodeEditorPanel` call `useWorkflowStore.getState().appendEvent(event)` for each parsed event (or delete its parser and use `runWorkflow`), and delete the unused half. (COD-frontend-stores-2)
- **[P2] Keymap without dispatch ownership.** Principle 2. Symptom: cognitive load and a Settings UI that lies. **Fix:** add `registerAction(id, handler)` to the keybindings store with one global keydown listener (`bindingFor` + `matchesEvent`), and drop defaults that have no registered handler. (COD-frontend-stores-4)
- **[P2] No request generation in fetch slices.** Principle 6 / 18. Symptom: unknown unknowns. **Fix:** a small `latest()` helper (a per-slice counter with `if (gen !== current) return`) applied in `sec.ts`, `earnings.ts`, `macro.ts`, `quant.ts` and `analyst-ratings.ts`. Also stop `loadFilings` from writing `activeIdentifier`. (COD-frontend-stores-5)
- **[P2] Error converted to a false empty.** Principle 8. `agents.ts:223-227`. **Fix:** use `sidecarGet` and set `customStatus:"error"` like the sibling does. (COD-frontend-stores-6)

## Persona walkthrough

**Tactical Tornado.** Asked to "add chat tabs", the Tactical Tornado wrote `agent-spaces.ts` beside the existing `research-spaces.ts`. It grabs `useChatHistoryStore.getState().messages` and calls `loadMessages` (`agent-spaces.ts:60-63`), exactly as research spaces do (`research-spaces.ts:185`), because that already worked. Asked to "run workflows", it wrote the SSE loop inside `NodeEditorPanel.tsx:386` because the panel needed local row state, and left `workflow.ts` for "the dispatcher". Asked for "remappable shortcuts", it built the table and the Settings UI and wired the one binding it was testing (`AgentDock.tsx:70`). In each case the test file for the store is green (`agent-spaces.test.ts`, `workflow.test.ts`, `keybindings.test.ts`) because the store is correct in isolation.

**Strategic Thinker.** The Strategic Thinker would ask "who owns this decision?" before adding a store. Threads belong in the conversation store, which must know about streaming. Workflow runs belong in the workflow store, with the panel as a view over `selectRunLog`. Shortcuts belong to the keymap, which must own dispatch or not offer remapping. Fetch slices get one helper that owns status, error, staleness and transport (`sidecarGet` / a new `sidecarPost`). None of this is a rewrite: each is a one-owner move of code that already exists.

## Minor observations

- `keybindings.ts:389-395`: a no-shift combo also matches with Shift held, so `mod+b` fires on ⌘⇧B, and `conflicts()` cannot see the overlap.
- `brief.ts:198-205`: the `stale_run` guard only applies in the `in_flight` phase. A late publish from an older run lands over a newer `published` brief. This is reachable once finding 1's concurrent sends happen. The watchdog clock only ticks while `BriefPanel`'s `InFlightView` is mounted (`BriefPanel.tsx:399-406`).
- `command-palette.ts:201-208` says the corpus is "Called ... on each render". In fact `CommandPalette.tsx:122` memoises it with `[]`, so agents or plugins that load while the palette is open do not appear. `useCommandPalette()` without a selector (`CommandPalette.tsx:70,118`) re-renders on every store change.
- `safety.ts:166-177` hand-lists every `BrokerId` for `EMPTY_STATIC_IP_STATUS` (typed `Record`, so the compiler catches drift). This is order-only state that goes with the trading removal.
